# مجلس — غرف شات

باك إند بـ Rust (axum + WebSocket) وفرونت إند بـ React، منفصلين تماماً.

```
chat/
├── backend/    Rust — REST للحسابات والغرف، WebSocket للرسائل
└── frontend/   React + TypeScript + Vite
```

## التشغيل

محتاج ترمينالين.

**الباك:**
```bash
cd chat/backend
cp .env.example .env        # وحط JWT_SECRET
cargo run
```
بيسمع على `http://127.0.0.1:3000`.

**الفرونت:**
```bash
cd chat/frontend
npm install
npm run dev
```
بيفتح على `http://localhost:5173`.

> `ALLOWED_ORIGINS` في `.env` بتاع الباك لازم تحتوي عنوان الفرونت، وإلا المتصفح هيرفض الطلبات.

## الـ API

| الطريقة | المسار | التوثيق | الوظيفة |
|---|---|---|---|
| POST | `/api/auth/register` | — | حساب جديد، بيرجّع توكن |
| POST | `/api/auth/login` | — | دخول، بيرجّع توكن |
| GET | `/api/auth/me` | Bearer | بيانات الحساب الحالي |
| GET | `/api/rooms` | Bearer | قائمة الغرف |
| POST | `/api/rooms` | Bearer | غرفة جديدة |
| GET | `/api/rooms/{id}/messages` | Bearer | تاريخ الغرفة |
| GET | `/ws?token=…&room=…` | query | الاتصال الحيّ |

## بروتوكول الـ WebSocket

كل الرسائل JSON، والحقل `type` بيحدد الشكل.

**من العميل:**
```jsonc
{ "type": "send", "body": "..." }   // رسالة
{ "type": "typing" }                // بيكتب دلوقتي
```

**من الخادم:**
```jsonc
{ "type": "history",  "messages": [...] }      // مرة واحدة عند الدخول
{ "type": "message",  "id": "...", "author": "...", "body": "...", "sent_at": 0 }
{ "type": "presence", "users": ["..."] }
{ "type": "typing",   "user": "..." }
{ "type": "system",   "text": "..." }          // دخول/خروج
{ "type": "error",    "text": "..." }          // للعميل ده وحده
```

## قرارات التصميم

**البث بـ JSON مُسلسَل جاهز.** قناة كل غرفة نوعها `broadcast::Sender<Arc<str>>` مش `Sender<ServerEvent>`. يعني السلسلة بتحصل مرة واحدة لكل رسالة بدل مرة لكل مشترك — مع ١٠٠ شخص في الغرفة، ده الفرق بين ١٠٠ عملية serialize وواحدة، والتوزيع بعدها مجرد نسخ `Arc`.

**أقفال `std` مش `tokio`.** الحالة المشتركة بتستخدم `std::sync::RwLock` لأنه أسرع. الشرط إن القفل مايتمسكش عبر `.await` — كل دالة في `state.rs` بتاخد القفل وتسيبه قبل ما ترجّع.

**Argon2 في `spawn_blocking`.** التجزئة مصمَّمة تكون بطيئة وتاكل ~١٩ ميجا رام. لو اشتغلت على خيط async هتوقّف باقي الاتصالات، فكل نداء بيتحوّل لخيط منفصل.

**التحقق قبل الترقية.** التوكن والغرفة بيتفحصوا قبل ما السوكِت يتفتح، فالرفض بيرجع كرد HTTP بسبب واضح بدل ما نفتح اتصال ونقفله.

**عدّاد اتصالات لكل مستخدم.** فتح تابين في المتصفح = اتصالين، بس المستخدم بيظهر مرة واحدة في قائمة الحضور، وإشعار الخروج مابيتبعتش غير مع آخر جلسة.

**العميل البطيء بيفقد رسايل، مايتقطعش.** لما `broadcast` ترجّع `Lagged` بنبعت إشعار ونكمّل بدل ما نقفل الاتصال.

**قناة خاصة لكل اتصال.** الأخطاء اللي تخص عميل واحد (رسالة طويلة، تعدّي الحد) بتروح له لوحده عبر `mpsc` منفصلة، مش على قناة بث الغرفة.

## حدود النسخة الحالية

- **التخزين في الذاكرة.** إعادة تشغيل الخادم بتمسح المستخدمين والغرف والرسائل. الوصول كله ماشي على `AppState` عشان تحويلها لداتابيز يبقى في ملف واحد.
- **خادم واحد.** قنوات البث في الذاكرة، فمافيش توزيع على أكتر من نسخة من غير طبقة زي Redis pub/sub.
- **تاريخ محدود.** آخر `HISTORY_LIMIT` رسالة لكل غرفة (افتراضي ١٠٠).
