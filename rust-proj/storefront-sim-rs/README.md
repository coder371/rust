# storefront-sim-rs

نسخة راست من `storefront-sim` — نفس مراحل رندر صفحة المتجر في `core-service`،
عشان نقارن عدد الصفحات اللي كل واحد يقدر يعملها في الثانية.

## التكافؤ

| | نود | راست |
|---|---|---|
| محرك القوالب | Nunjucks | MiniJinja |
| القوالب | نفس الـ ١٩ ملف | نفس الـ ١٩ ملف |
| ناتج HTML | ٥١٬٠٧١ بايت | ٥١٬٠٥١ بايت |
| استعلامات مونجو | ٢١ | ٢١ |
| عمليات ريدس | ٤ | ٤ |

فرق الـ٢٠ بايت من تهريب `/` في MiniJinja وترتيب مفاتيح JSON — شكلي بحت.

## التشغيل

```bash
cargo build --release

WORKERS=1 ./target/release/storefront-sim              # الكود الحالي، نواة واحدة
SIM_MODE=tuned WORKERS=6 ./target/release/storefront-sim
NJK_CACHE=1 ./target/release/storefront-sim            # إصلاح واحد بس
```

نفس أعلام نسخة نود: `NJK_CACHE` و`PAGE_CACHE` و`PARALLEL_FIELDS` و`SIM_MODE=tuned`.

## حاجتان اتصلّحوا في كود راست أثناء القياس

أول قياس طلّع راست **أبطأ** من نود بعد الإصلاح (٥٧١ مقابل ١٤٥٧). السبب كان في
الكود مش في اللغة:

1. **الكاش كان بيعمل نسخة عميقة.** كان بيخزّن `serde_json::Value` فكل إصابة كاش
   بتنسخ الشجرة كلها وتحوّلها للقالب من جديد. نود بيرجّع نفس المرجع. الحل: نخزّن
   القيمة بالشكل اللي القالب بيستهلكه.

2. **السياق كان بيتحوّل ذهاباً وإياباً.** `json!` حوالين قيمة جاهزة كان بيحوّلها
   لـ JSON وبعدين يرجّعها. الحل: `context!` مباشرة.

بعد الاتنين بقت ١٩٣٧ صفحة/ث.
